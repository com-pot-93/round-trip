The process begins with "INQ transmits the transaction data request to the IP". After this, "IP checks the request of the INQ". The outcome of IP's examination will determine the next step. If the request is validated, the "IP answers the question of the INQ". The process ends after the IP has answered the INQ's question.

This process involves two main entities: INQ and IP. INQ is responsible for the "Transaction Request" which includes transmitting the transaction data request to the IP, and IP handles the "Transaction Processing" which involves checking the INQ's request and responding to the INQ's question. 

The process flows from the start to end in the following order: "INQ transmits the transaction data request to the IP" -> "IP checks the request of the INQ" -> "Outcome of IP's examination" -> "IP answers the question of the INQ" -> end. 

Moreover, there are also message flows between tasks. A message is sent from "INQ transmits the transaction data request to the IP" to "IP checks the request of the INQ", and another message is sent from "IP checks the request of the INQ" to "IP answers the question of the INQ".
