The process begins with "INQ" transmitting the transaction data request. After this, "IP" checks the request. Depending on the outcome of the request check, which is determined at the "Check request outcome" point, "IP" then answers the question. The process concludes at the "end" point. 

The process is divided into two main sections or "pools", one for "INQ" and one for "IP". The "INQ" pool contains the initial transmission of the transaction data request and the start of the process. The "IP" pool includes the checking of the request, the answering of the question, the decision point for the request outcome, and the end of the process. 

The flow of the process is as follows: it starts, then "INQ" transmits the transaction data request, "IP" checks the request, the request outcome is checked, "IP" answers the question, and finally, the process ends. 

There are also two message flows in the process. The first is from the transmission of the transaction data request by "INQ" to the checking of the request by "IP". The second is from the checking of the request by "IP" to the answering of the question by "IP".
